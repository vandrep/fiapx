# Evolução v2 da avaliação do harness

> Navegação: [baseline v1](README.md) · [documentação](../../README.md) · [roadmap](../../acompanhamento/roadmap.md)

O contrato [`scenarios-v2.json`](scenarios-v2.json) preserva os três cenários da baseline e acrescenta a [navegação pelo mapa arquitetural](prompts/architecture-map.md). A ausência de `--contract` continua selecionando a baseline v1, mantendo sua evidência histórica reproduzível.

## EVAL-HARNESS-ARCH-001 — Navegação arquitetural

- Deve reconhecer que a aplicação-alvo ainda não existe e não afirmar implementação.
- Deve identificar exatamente `CTX-CMP-003`, `CMP-18..25`, `DEC-0002` e os quanta `gestao-trabalhos`, `producao-resultados` e `notificador`.
- Deve tratar Keycloak como plataforma, `DEC-0003` como `em_analise` e Java/Quarkus como preferência.
- Não pode usar modelos históricos ou propostas como definição corrente.
- Fontes mínimas: `AGENTS.md`, `ARCHITECTURE.md` e roteador; o total fica limitado a sete fontes.

## Execução

Os gates determinísticos de ambos os contratos integram a [validação agregada](../../../scripts/validar-harness.sh):

```bash
bash scripts/validar-harness.sh check
```

Para uma coleta viva, use um diretório externo ao repositório:

```bash
bash scripts/avaliar-harness.sh run --label candidato-v1 --output-dir /tmp/fiapx-harness-v1
bash scripts/avaliar-harness.sh run --contract scenarios-v2.json --scenario EVAL-HARNESS-ARCH-001 --fail-fast --label candidato-arquitetura --output-dir /tmp/fiapx-harness-arquitetura
```

A execução v2 sem `--scenario` continua disponível como regressão deliberada dos quatro cenários. A avaliação viva não é gate de PR: ela depende da versão congelada do Codex, consome tokens e exige revisão semântica. CI executa fixtures, rubricas e contrafactuais sem chamar o modelo.
